# DeepSeek Chat for Obsidian — 功能设计

> 状态：0.1.0 已按本设计实现（2026-11-14）。本文保留为最初的设计记录，实际行为以代码和 README 为准。
> 依据：DeepSeek 官方文档「构建 Chatbot」及其链接的各功能页（2026-11 版）

---

## 1. 这个插件是什么

一个**开源、非官方**的 Obsidian 插件。用户填入自己的 DeepSeek API Key，就能在 Obsidian 侧栏里使用 DeepSeek 官方「构建 Chatbot」指南里的全部能力：联网搜索、深度思考搜索、读文件、读链接、内容安全、会话标题、朗读、语音输入。

它要同时做到两件事：

1. **能力展示台**：每一项 API 能力在界面上都有看得见的入口和过程展示，用户用一遍就知道「DeepSeek API 能做到什么」，费用也是透明的。
2. **日常可用的对话工具**：和 Obsidian 结合，能拿当前笔记、选中文字、库里的文件当上下文，回答也能一键写回笔记。

它**不做**的事：不做本地 Agent（不执行命令、不批量改文件）、不做全库向量检索、不接其他模型厂商。范围收窄，才能把 DeepSeek 这一家的能力做透。

### 不绑定任何人的仓库

- 所有路径、文件夹、语言、价格都来自设置项，代码里没有任何写死的个人约定。
- 默认值对一个空库也能直接工作。
- 界面中英双语，跟随 Obsidian 的语言设置。

## 2. 给谁用、解决什么问题

| 用户 | 现在的麻烦 | 插件带来的变化 |
|---|---|---|
| 想在笔记里用 AI 的普通用户 | 本地 Agent 要装命令行、要订阅，门槛高；不少聊天插件联网要另配搜索服务 | 填一个 Key 就能联网问答、读链接、读 PDF，手机上也能用 |
| 想了解 DeepSeek API 的开发者 / 内容创作者 | 文档里的能力很多，不跑代码很难直观感受 | 每项能力一个开关，过程（搜了什么、读了哪页、花了多少钱）都摊开展示 |
| 研究 / 写作场景 | 查资料、读网页、读论文要在多个工具之间来回切换 | 在侧栏里搜、读、问，答案连同出处存成笔记 |

## 3. 功能清单

优先级：**P0** = 第一个公开版本必须有；**P1** = 第二版；**P2** = 以后再说。

### 3.1 对话核心

| 功能 | 说明 | 优先级 |
|---|---|---|
| 多轮对话 | 侧栏对话视图，流式输出。API 本身无状态，由插件保存完整历史，每轮全部重发 | P0 |
| 模型选择 | `deepseek-flash`（默认）/ `deepseek-v4-pro`；模型列表放在设置里可编辑，应对改名 | P0 |
| 思考模式 | 开 / 关，以及思考强度（low / high / max）。思考过程默认折叠，点开能看 | P0 |
| 停止生成 | 随时中断当前回答 | P0 |
| 重新生成 / 编辑上一条再发 | 常规对话操作 | P1 |
| 续写 | 回答被截断（`max_tokens`）时出现「继续」按钮。用过联网工具的回答不能续写，按钮置灰并说明原因 | P1 |
| 系统提示词 | 全局默认一份；单个会话可以覆盖；支持保存多份预设 | P1 |

### 3.2 官方指南的九项能力

| # | 能力 | 界面上怎么体现 | 优先级 |
|---|---|---|---|
| 1 | **联网搜索** | 输入框旁的「联网」开关。回答上方显示一张「搜索过程卡」：搜了哪些词、返回哪些结果（标题、站点、图标、摘要）。正文里的引用标成角标，悬停显示来源，点击打开网页 | P0 |
| 2 | **深度思考搜索** | 联网和思考同时打开时自动进入。过程卡变成时间线：思考 → 搜索 → 打开网页 → 页内查找，最多约 20 步，每一步都可以展开 | P0 |
| 3 | **文件输入** | 拖入或选择文件。PDF / Word / PPT / 图片先上传解析，可选「只要文字」或「保留版面与插图」；md / txt / csv / json / 代码按纯文本上传（不收解析费）。附件以卡片形式出现在消息里，显示文件名、页数和解析状态 | P0 |
| 4 | **阅读链接** | 消息里直接贴链接（模型会考虑最后一条消息里的前 10 个）。过程卡显示读了哪些页面、哪些读取失败以及原因（无法访问 / 被拦截） | P0 |
| 5 | **内容安全** | 设置项「安全审核：关 / 高」。被拒答时，已经流式显示的文字撤回，换成可配置的提示语。审核消耗的 token 单独列在用量里 | P1 |
| 6 | **用户元信息** | 每轮自动在用户消息前插入「日期、星期、地点、平台、语言」，模型就知道「今天」是哪天。地点由用户在设置里填，可以留空 | P1 |
| 7 | **会话标题** | 第一轮自动生成标题，生成失败就退回用户第一句话的开头。标题可以手动改 | P0 |
| 8 | **朗读回答** | 每条回答旁边一个 🔊 按钮；音色 stella / tide；可选「回答生成完自动朗读」。用 WebSocket 流式合成，边生成边播放，默认去掉 Markdown 符号 | P2 |
| 9 | **语音输入** | 输入框旁的麦克风按钮，录音最长 120 秒，转写结果填进输入框，由用户确认后再发送 | P2 |

### 3.3 进阶 API 能力（展示用）

| 功能 | 说明 | 优先级 |
|---|---|---|
| 工具调用演示 | 内置几个只读的 Obsidian 工具：读当前笔记、按关键词搜库、列出某个文件夹。模型自己决定调哪个，过程可见。**默认不提供任何写入工具** | P1 |
| JSON 输出演示 | 一条命令：「从当前笔记提取结构化信息」，结果显示为 JSON 并可复制 | P2 |
| 图片理解 | 粘贴截图提问（仅 `deepseek-flash` 支持） | P1 |

### 3.4 用量与费用透明

这是「展示台」最打动人的部分，所以放在 P0。

- 每条回答底部一行小字：输入（缓存命中 / 未命中）、输出（含思考）、搜索次数、读页数，以及按当前时段（高峰 / 低谷）折算的金额。
- 会话顶部显示整个会话的累计花费。
- 价格表放在设置里，带默认值并可编辑（官方说明价格会调整），高峰时段按北京时间计算。
- 可选「显示原始请求 / 响应」开发者面板，方便学习 API。

### 3.5 和 Obsidian 的结合

| 功能 | 说明 | 优先级 |
|---|---|---|
| 当前笔记作上下文 | 输入框上方一个「附带当前笔记」的开关，显示笔记名 | P0 |
| 选中文字发问 | 编辑器右键菜单 / 命令：「用 DeepSeek 解释 / 总结 / 翻译选中内容」，打开侧栏并带上原文 | P0 |
| 库内文件当附件 | 用 `@` 或附件按钮从库里选文件，md 按纯文本发，PDF 走解析 | P1 |
| 回答写回笔记 | 每条回答可以「插入到光标处」「复制」「另存为新笔记」 | P0 |
| 会话导出为笔记 | 整个会话导出成 Markdown，引用来源附在文末 | P0 |
| 命令面板 | 新建会话、打开侧栏、朗读选中内容、语音输入等 | P0 |

### 3.6 会话管理

| 功能 | 说明 | 优先级 |
|---|---|---|
| 会话列表 | 侧栏顶部下拉或抽屉，可以搜索标题、重命名、删除（删除进系统回收站） | P0 |
| 自动保存 | 每轮结束后自动保存，重开 Obsidian 能接着聊 | P0 |
| 跨设备 | 会话文件放在库里，跟着用户自己的同步方案走 | P0 |

## 6. 数据与存储

**会话文件**：每个会话保存为库里的一个 `.json` 文件，默认放在 `DeepSeek Chats/`，文件夹由用户设置。

选 JSON 而不是 Markdown，是因为下一轮必须把思考签名、搜索块、读页签名、元信息**原样**发回去，Markdown 装不下这些内容，人也不该手改。想要可读版本，就用「导出为笔记」。

放在库里而不是插件目录，是为了让会话跟着用户自己的同步方案（官方同步、iCloud、Git）走，换设备也能接着聊。

```jsonc
{
  "version": 1,
  "id": "…",
  "title": "…",
  "createdAt": "…",
  "model": "deepseek-flash",
  "settings": { "thinking": true, "webSearch": true, "safety": "off" },
  "messages": [ /* Messages API 原样的 content blocks，含 signature / kind */ ],
  "usage": [ /* 每轮用量与折算金额 */ ],
  "attachments": [ /* file_id、文件名、页数、上传时间 */ ]
}
```

**插件设置**存在插件自己的 `data.json` 里，API Key 也在其中。README 会写明这一点，并提醒用户：如果用 Git 同步整个库，要把这个文件加进忽略列表。

## 7. 技术方案

- **协议**：统一走 **Messages API**（`/anthropic/v1/messages`）。九项能力它全部支持，流式事件的名字最清楚，还原生支持续写和元信息。TTS、ASR、文件上传走各自的独立接口。
- **网络**：流式请求用 `fetch` 读 SSE。如果遇到跨域限制，退回 Obsidian 的 `requestUrl`，这时一次性返回、没有逐字效果，界面上会提示。**这一点开工第一天就验证。**
- **语音**：TTS 用 WebSocket。浏览器里设置不了请求头，按官方支持的子协议方式 `tts, bearer.<key>` 认证，用 Web Audio 播放 PCM。ASR 只接受 WAV 和 Ogg Opus 格式，录音（webm）要在本地先转成 16-bit 单声道 WAV 再上传。
- **移动端**：`isDesktopOnly: false`，核心对话和联网在手机上都能用；麦克风等能力按平台检测，不支持就隐藏。
- **代码结构**：

```
src/
  api/        messages.ts（请求+SSE 解析）· files.ts · tts.ts · asr.ts · pricing.ts
  session/    store.ts（读写会话 JSON）· history.ts（组装下一轮 messages）
  ui/         ChatView.ts · MessageRenderer.ts · ProcessCard.ts · Composer.ts · SessionList.ts
  obsidian/   context.ts（当前笔记/选中）· tools.ts（只读工具）· export.ts
  i18n/       zh.ts · en.ts
  settings.ts · main.ts
```

- **渲染**：回答正文用 Obsidian 自带的 `MarkdownRenderer`，代码块、公式、双链都正常显示；不使用 `innerHTML`（这是社区插件审核的要求）。

## 8. 隐私与安全

- README 首屏写清楚：插件会把**你发送的内容、附带的笔记和上传的文件**发送到 DeepSeek 服务器；联网搜索和读链接由 DeepSeek 服务端执行。
- 没有任何遥测，不会把数据发给作者。
- 只有用户主动勾选、或通过工具调用读取时，才会附带笔记内容；工具调用在过程卡里逐条可见。
- 默认不提供任何写文件的工具。写回笔记只能由用户点按钮完成。

## 9. 开源与发布

- **仓库**：`obsidian-deepseek-chat`（GitHub 仓库名可以带 obsidian，插件 ID 不能带）。
- **插件 ID / 显示名**：暂定 `deepseek-chat` /「DeepSeek Chat」。README 和设置页注明「非官方，与 DeepSeek 无关联」。
- **许可证**：MIT。
- **发布**：GitHub Actions 在打 tag 时自动构建，附上 `main.js`、`manifest.json`、`styles.css`；在正式上架社区插件之前，先让用户通过 BRAT 安装测试版。
- **社区插件审核要点**：插件 ID 和名字里不带 "Obsidian"；在 README 里说明网络用途；不用 `innerHTML`；不写死路径；`onunload` 里清理干净；用 `Vault` 和 `FileManager` 的接口操作文件。
- **文档**：README 中英双语，包含截图 / GIF、获取 API Key 的步骤、费用说明、常见问题。

## 11. 已定的决定

1. 插件 ID `deepseek-chat`，显示名 `DeepSeek Chat`（社区目录规定名称不能含 Obsidian）；仓库与 README 标题用 Obsidian-DeepSeek Chat。
2. 会话以 JSON 存在库内 `DeepSeek Chats/`，可在设置里修改。
3. 九项能力在 0.1.0 一次做全，每项都可以在设置里开关。
4. 界面中英双语，跟随 Obsidian 语言；README 英文在前、中文在后。
5. 笔记库工具在对话框里有独立开关，默认关闭。
